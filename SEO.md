# Индексация и сопровождение SEO

Основной адрес: https://hram.lt/ (Hostinger). Зеркало для совместимости: https://maksimas-win.github.io/bukiskis-parama/ — его страницы указывают canonical на hram.lt, поэтому отдельно не продвигаются.

## Что формирует сборка

- Шесть доступных без JavaScript информационных страниц с `index,follow,max-image-preview:large`.
- Локализованные title, description, OpenGraph и Twitter summary.
- Canonical на `/ru/index.html`, `/lt/index.html`, `/en/index.html`, `/pl/index.html`, `/de/index.html`, `/uk/index.html`. Корневая страница — копия русской с тем же canonical, поэтому повторно в sitemap не включается.
- Взаимные hreflang для шести языков и x-default. Для страниц конфиденциальности ссылки указывают на их переводы.
- Microdata schema.org на существующем HTML без inline-скриптов и ослабления CSP:
  - `WebPage` с `name`, `description`, `inLanguage`, `url`, `dateModified` (из `contentUpdated`) и `isPartOf` → `WebSite`;
  - `FAQPage` с `Question`/`Answer` для раздела вопросов.
  Google с 2023 года показывает расширенный результат FAQ в основном для государственных и медицинских сайтов, поэтому разметка не обещает особого вида в выдаче; она остаётся полезной для Bing, Яндекса и поисковых ИИ-ассистентов.
- `sitemap.xml` только с шестью каноническими индексируемыми страницами. Страницы конфиденциальности, 404 и файл подтверждения владения исключены.
- Файл подтверждения Google из `searchConsoleVerificationFile`: `googled8db1e57cec5f564.html`. Он создаётся при каждой сборке; удалять его после подтверждения не следует.

`publicBaseUrl` хранит постоянный адрес; `SITE_URL` может переопределить его при сборке. При смене домена нужно обновить конфигурацию и workflow. `contentUpdated` — дата содержательного изменения индексируемых страниц, используемая в sitemap и `dateModified`; не обновлять автоматически при каждой сборке. `reviewed` — отдельная дата проверки источников.

Индексация справочного материала не меняет `recipientVerified` и `gpmBankAccountVerified`. Предупреждения о статусе получателя остаются на странице.

## Google Search Console

1. Добавить ресурс `https://hram.lt/` (префикс URL) либо доменный ресурс `hram.lt` (подтверждение DNS-записью в Hostinger).
2. Для префикса URL подтвердить владение HTML-файлом: https://hram.lt/googled8db1e57cec5f564.html
3. В разделе Sitemaps отправить `https://hram.lt/sitemap.xml`.
4. Через «Проверка URL» → «Проверить страницу на сайте» убедиться, что Googlebot получает HTTP 200 и сам гид, а не страницу проверки браузера CDN (см. ниже). Затем можно запросить индексирование.
5. Следить за отчётами «Индексирование страниц» и «Основные интернет-показатели». Успешная отправка sitemap или запроса не гарантирует включения в индекс либо позиции.

## CDN Hostinger и роботы

CDN Hostinger (`Server: hcdn`) может отвечать на часть запросов страницей «Checking your browser before accessing» с HTTP 403 и `noindex,nofollow` — так он защищается от ботов. При проверке 5 октября 2026 Lighthouse из PageSpeed Insights и проверка из GitHub Actions получали сайт нормально, но после серии быстрых запросов с одного адреса CDN начинал отвечать этой страницей. Если такая страница попадёт поисковому роботу или сервису предпросмотра ссылок, страница может выпасть из индекса, а превью в мессенджерах — пропасть.

- В hPanel проверить настройки безопасности CDN и защиты от ботов: проверенные поисковые роботы (Googlebot, Bingbot, YandexBot) и сервисы предпросмотра ссылок не должны получать проверку браузера.
- Периодически запускать «Проверку URL» в Search Console и смотреть отчёт об ошибках сканирования.

## Скорость (Core Web Vitals)

Скорость входит в сигналы ранжирования. PageSpeed Insights, мобильная версия, 5 октября 2026: производительность 79, доступность 100, рекомендации 100, SEO 100; LCP 4,1 с, CLS 0,175.

- LCP — изображение обращения прихода в окне, которое открывается при первом входе (PNG 2750×1938, 597 КБ). Окно открывается скриптом, поэтому браузер узнаёт о файле поздно. Уменьшенная копия для окна (например, WebP шириной около 1400 px) со ссылкой на оригинал сократила бы LCP примерно на 0,5–1 с. Это меняет показываемый файл, поэтому делается только по решению владельца (см. AGENTS.md).
- CLS исправлен в 0.5.6: место под изображение обращения резервируется до загрузки, а 3D-вступление начинает с реальной высоты шапки.

## Bing, Яндекс и внешние ссылки

- Bing Webmaster Tools: импортировать подтверждённый ресурс из Search Console либо подтвердить отдельно и отправить тот же sitemap. Подтверждение Google не подключает Bing автоматически.
- Яндекс Вебмастер: для русскоязычной аудитории стоит добавить `https://hram.lt/`, подтвердить владение (HTML-файл или метатег — код выдаёт Яндекс) и отправить sitemap. Код подтверждения нужно добавить в `src/site.config.json` и сборку отдельной задачей.
- Обычная ссылка на этот гид с основного сайта прихода поможет посетителям и поисковым роботам находить его. Изменения основного сайта выполняются отдельной задачей.
- Картинки для превью в соцсетях (`og:image`) пока нет: при отправке ссылки показывается только текст. Нейтральная картинка 1200×630 без религиозных символов (см. AGENTS.md) улучшила бы превью; она не влияет на позиции напрямую.

## Зеркало GitHub Pages

Поисковые роботы читают robots.txt в корне хоста: `https://maksimas-win.github.io/robots.txt`, а не в папке проекта, поэтому `bukiskis-parama/robots.txt` на зеркале не действует. Это не мешает: canonical всех страниц зеркала указывает на hram.lt.

## Проверка изменений

Запустить `npm run build` и `npm test`. После публикации проверить HTTP 200, отсутствие заголовка X-Robots-Tag: noindex, метатеги всех шести страниц, sitemap и точное содержимое файла Google. Не считать зелёную сборку доказательством индексирования.
